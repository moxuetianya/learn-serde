# 第二章: Serde 数据模型

**源码参考**: `serde_core/src/ser/mod.rs` 和 `serde_core/src/de/mod.rs`

## Serde 数据模型 —— 28 种类型

Serde 不直接操作 Rust 类型,而是定义了一套称为 **serde data model** 的抽象类型体系。`Serialize` 将 Rust 类型映射到数据模型,`Serializer` 将数据模型转换为字节/字符串。

Serde 数据模型共 **28 种类型**:

### 1. 14 种基本类型 (Primitives)

| 类型 | Serializer 方法 | 对应 Rust 类型 |
|------|----------------|---------------|
| `bool` | `serialize_bool(v: bool)` | `bool` |
| `i8` | `serialize_i8(v: i8)` | `i8` |
| `i16` | `serialize_i16(v: i16)` | `i16` |
| `i32` | `serialize_i32(v: i32)` | `i32` |
| `i64` | `serialize_i64(v: i64)` | `i64` |
| `i128` | `serialize_i128(v: i128)` | `i128` |
| `u8` | `serialize_u8(v: u8)` | `u8` |
| `u16` | `serialize_u16(v: u16)` | `u16` |
| `u32` | `serialize_u32(v: u32)` | `u32` |
| `u64` | `serialize_u64(v: u64)` | `u64` |
| `u128` | `serialize_u128(v: u128)` | `u128` |
| `f32` | `serialize_f32(v: f32)` | `f32` |
| `f64` | `serialize_f64(v: f64)` | `f64` |
| `char` | `serialize_char(v: char)` | `char` |

`i128` 和 `u128` 有默认实现(返回错误),因为很多格式不支持 128 位整数。

### 2. 字符串 (String)

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `str` | `serialize_str(v: &str)` | `&str`, `String` |
| `bytes` | `serialize_bytes(v: &[u8])` | `&[u8]`, `Vec<u8>` |

```rust
// 源码: serde_core/src/ser/mod.rs ~420-460
fn serialize_str(self, v: &str) -> Result<Self::Ok, Self::Error>;
fn serialize_bytes(self, v: &[u8]) -> Result<Self::Ok, Self::Error>;
```

有些格式区分字符串和字节(如 JSON 将 bytes 编码为 base64),有些不区分(如 Bincode)。

### 3. Option

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `none` | `serialize_none()` | `None` |
| `some(T)` | `serialize_some(v: &T)` | `Some(val)` |

### 4. 单元类型 (Unit)

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `unit` | `serialize_unit()` | `()` |
| `unit_struct` | `serialize_unit_struct(name)` | `struct Unit;` |
| `unit_variant` | `serialize_unit_variant(name, idx, variant)` | `enum E { V }` |

### 5. 序列 (Sequence)

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `seq` | `serialize_seq(len)` | `Vec<T>`, `[T]` |
| `tuple` | `serialize_tuple(len)` | `(T1, T2, ...)` |
| `tuple_struct` | `serialize_tuple_struct(name, len)` | `struct S(T1, T2)` |
| `tuple_variant` | `serialize_tuple_variant(name, idx, variant, len)` | `enum E { V(T1, T2) }` |

### 6. 映射 (Map)

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `map` | `serialize_map(len)` | `HashMap`, `BTreeMap` |
| `struct` | `serialize_struct(name, len)` | `struct S { f1, f2 }` |
| `struct_variant` | `serialize_struct_variant(name, idx, variant, len)` | `enum E { V { f1, f2 } }` |

### 7. Newtype

| 类型 | Serializer 方法 | 对应 Rust |
|------|----------------|-----------|
| `newtype_struct` | `serialize_newtype_struct(name, v)` | `struct S(T)` |
| `newtype_variant` | `serialize_newtype_variant(name, idx, variant, v)` | `enum E { V(T) }` |

## 映射规则总结

```
Rust 类型                       → Serde 数据模型
===========================================================
bool                            → bool
i32                             → i32
&str                            → str
&[u8]                           → bytes
()                              → unit
Option::None                    → none
Option::Some(v)                 → some(v)
struct Unit;                    → unit_struct("Unit")
struct NewType(u8);             → newtype_struct("NewType", u8)
struct Tuple(u8, u16);          → tuple_struct("Tuple", 2)
enum E { V }                    → unit_variant("E", 0, "V")
enum E { V(u8) }               → newtype_variant("E", 0, "V", u8)
enum E { V(u8, u16) }           → tuple_variant("E", 0, "V", 2)
enum E { V { x: u8 } }         → struct_variant("E", 0, "V", 1)
struct S { x: u8, y: u16 }     → struct("S", 2)
Vec<T>                          → seq
[u8; 4]                         → tuple(4)
HashMap<K, V>                   → map
```

## 复合类型的"状态机"

对于 seq、tuple、map、struct 等复合类型,Serializer 不是一次性序列化,而是返回一个**状态机特质**的对象:

```rust
// 源码: serde_core/src/ser/mod.rs ~1518-2000

// 序列化序列
pub trait SerializeSeq {
    type Ok; type Error;
    fn serialize_element<T: Serialize>(&mut self, value: &T) -> Result<(), Self::Error>;
    fn end(self) -> Result<Self::Ok, Self::Error>;
}

// 序列化 Map
pub trait SerializeMap {
    type Ok; type Error;
    fn serialize_key<T: Serialize>(&mut self, key: &T) -> Result<(), Self::Error>;
    fn serialize_value<T: Serialize>(&mut self, value: &T) -> Result<(), Self::Error>;
    fn end(self) -> Result<Self::Ok, Self::Error>;
}

// 序列化 Struct
pub trait SerializeStruct {
    type Ok; type Error;
    fn serialize_field<T: Serialize>(&mut self, key: &str, value: &T) -> Result<(), Self::Error>;
    fn skip_field(&mut self, key: &str) -> Result<(), Self::Error>;
    fn end(self) -> Result<Self::Ok, Self::Error>;
}

// ... 还有 SerializeTuple, SerializeTupleStruct,
//     SerializeTupleVariant, SerializeStructVariant
```

### 使用流程示例

```rust
// 对于 struct Point { x: i32, y: i32 }
// 序列化过程:
let mut s = serializer.serialize_struct("Point", 2)?;
s.serialize_field("x", &self.x)?;
s.serialize_field("y", &self.y)?;
s.end()
```

## 反序列化侧的数据模型

反序列化侧同样有 28 种类型,通过 `Deserializer` 的方法暴露:

| 方法 | 说明 |
|------|------|
| `deserialize_bool` | 期望 bool |
| `deserialize_i8`..`deserialize_i128` | 期望有符号整数 |
| `deserialize_u8`..`deserialize_u128` | 期望无符号整数 |
| `deserialize_f32`, `deserialize_f64` | 期望浮点 |
| `deserialize_char` | 期望字符 |
| `deserialize_str` | 期望 &str(可借用) |
| `deserialize_string` | 期望 String(所有权转移) |
| `deserialize_bytes` | 期望 &[u8] |
| `deserialize_byte_buf` | 期望 Vec<u8> |
| `deserialize_option` | 期望 Option |
| `deserialize_unit` | 期望 unit |
| `deserialize_unit_struct` | 期望 unit struct |
| `deserialize_newtype_struct` | 期望 newtype struct |
| `deserialize_seq` | 期望序列 |
| `deserialize_tuple` | 期望 tuple |
| `deserialize_tuple_struct` | 期望 tuple struct |
| `deserialize_map` | 期望 map |
| `deserialize_struct` | 期望 struct(带字段名) |
| `deserialize_enum` | 期望 enum |
| `deserialize_identifier` | 期望字段名/变体名 |
| `deserialize_ignored_any` | 期望任意类型并丢弃 |
| `deserialize_any` | 输入自描述时使用(JSON)<br>根据输入内容类型决定调用哪个 visit_* |

关键区别: 反序列化是 **type-driven** 还是 **content-driven**。

- **type-driven**: 调用方知道期望的类型,调用对应的 `deserialize_*` 方法。几乎所有格式都支持。
- **content-driven**: 格式自身描述数据的类型(如 JSON),Deserializer 实现 `deserialize_any` 来分析输入。
- **self-describing formats**: JSON, YAML, MessagePack 等支持 `deserialize_any`
- **non-self-describing formats**: Bincode, Postcard 不支持 `deserialize_any`

## 关键宏: forward_to_deserialize_any!

```rust
// 源码: serde_core/src/macros.rs
// 对于 non-self-describing 格式,几乎所有 deserialize_* 方法
// 都可以直接 forward 到 deserialize_any,由 Visitor 决定如何处理

forward_to_deserialize_any! {
    bool i8 i16 i32 i64 i128 u8 u16 u32 u64 u128 f32 f64 char
    str string bytes byte_buf option unit unit_struct
    newtype_struct seq tuple tuple_struct map struct
    enum identifier ignored_any
}
```

这个宏为每个类型生成一个方法,内部调用 `self.deserialize_any(visitor)`。
