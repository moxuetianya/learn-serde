# 第十五章: 枚举反序列化 —— 四种 tag 策略的深度剖析

**源码参考**: `serde_derive/src/de/{enum_.rs, enum_externally.rs, enum_internally.rs, enum_adjacently.rs, enum_untagged.rs}`

## 枚举反序列化的挑战

枚举反序列化比结构体复杂得多,因为需要**先确定 variant,再反序列化内容**。

四种策略对应不同的确定 variant 的方式:

| 策略 | 如何确定 variant | JSON 示例 |
|------|-----------------|-----------|
| External | 通过外层 key | `{"KeyPress": "a"}` |
| Internal | 通过内层 tag 字段 | `{"type": "KeyPress", "value": "a"}` |
| Adjacent | 通过 tag 字段 + content 字段 | `{"t": "KeyPress", "c": "a"}` |
| Untagged | 尝试每个 variant | `"a"` |

## 1. External (默认) —— `serde_derive/src/de/enum_externally.rs`

```rust
// 生成的代码概念:
impl<'de> Deserialize<'de> for Event {
    fn deserialize<D>(d: D) -> Result<Self, D::Error> {
        d.deserialize_enum("Event", &["Click", "KeyPress"], EventVisitor)
    }
}

// EventVisitor::visit_enum 接收 EnumAccess
fn visit_enum<A>(self, data: A) -> Result<Event, A::Error>
where A: EnumAccess<'de>
{
    // data.variant() 返回 (variant_name, VariantAccess)
    use serde::de::VariantAccess;

    // 生成 __Field 枚举(变体名标识符)
    let (field, variant) = data.variant::<__Field>()?;

    match field {
        __Field::Click => {
            // struct variant → struct_variant
            let (x, y) = variant.struct_variant(&["x", "y"], ClickVisitor)?;
            Ok(Event::Click { x, y })
        }
        __Field::KeyPress => {
            // newtype variant → newtype_variant
            Ok(Event::KeyPress(variant.newtype_variant()?))
        }
        __Field::Exit => {
            // unit variant → unit_variant
            variant.unit_variant()?;
            Ok(Event::Exit)
        }
    }
}
```

## 2. Internal tag —— `serde_derive/src/de/enum_internally.rs`

```rust
// 源码: serde_derive/src/de/enum_internally.rs (106 行,相对简洁)
// 关键: 使用 TaggedContentVisitor 从任意格式中提取 tag

// 生成的代码:
fn deserialize<D>(d: D) -> Result<Self, D::Error> {
    const VARIANTS: &[&str] = &["Click", "KeyPress", "Exit"];

    // 1. 先用 TaggedContentVisitor 提取 tag + 剩余内容
    let (variant, content) = d.deserialize_any(
        _serde::__private::de::TaggedContentVisitor::<__Field>::new(
            "type", VARIANTS
        )
    )?;

    // 2. 用 ContentDeserializer 从内容中反序列化
    let deserializer = _serde::__private::de::ContentDeserializer::new(content);
    match variant {
        __Field::Click => {
            Deserialize::deserialize(deserializer).map(Event::Click)
        }
        __Field::KeyPress => {
            Deserialize::deserialize(deserializer).map(Event::KeyPress)
        }
        __Field::Exit => Ok(Event::Exit),
    }
}

// TaggedContentVisitor 的工作流程:
// 1. deserialize_any 将输入转为 Content
// 2. 从 Content::Map 中提取 tag 字段
// 3. 返回 (tag_value, remaining_content)
```

## 3. Adjacent tag —— `serde_derive/src/de/enum_adjacently.rs`

```rust
// 源码: serde_derive/src/de/enum_adjacently.rs (324 行,最复杂的策略)
// 挑战: tag 和 content 的键可能以任意顺序出现

// 生成的代码(概念):
struct AdjacentVisitor;

impl<'de> Visitor<'de> for AdjacentVisitor {
    fn visit_map<A>(self, mut map: A) -> Result<Event, A::Error> {
        let mut tag: Option<__Field> = None;
        let mut content: Option<_serde::__private::Content> = None;

        while let Some(key) = map.next_key()? {
            match key {
                TagOrContent::Tag => {
                    tag = Some(map.next_value::<__Field>()?);
                }
                TagOrContent::Content => {
                    content = Some(map.next_value::<_serde::__private::Content>()?);
                }
            }
        }

        let tag = tag.ok_or_else(|| de::Error::missing_field("tag"))?;
        let content = content.ok_or_else(|| de::Error::missing_field("content"))?;

        // 用 ContentDeserializer 反序列化内容
        match tag {
            __Field::Click => {
                let (x, y) = Deserialize::deserialize(
                    _serde::__private::de::ContentDeserializer::new(content)
                )?;
                Ok(Event::Click { x, y })
            }
            // ...
        }
    }

    // 也支持 format: ["KeyPress", "a"]
    fn visit_seq<A>(self, mut seq: A) -> Result<Event, A::Error> {
        let tag: __Field = seq.next_element()?.ok_or(...)?;
        let content = _serde::__private::de::ContentDeserializer::new(
            seq.next_element::<_serde::__private::Content>()?.ok_or(...)?
        );
        match tag { ... }
    }
}
```

### TagOrContent —— 字段名枚举

```rust
// 用于标识当前 key 是 tag 还是 content
enum TagOrContent {
    Tag,
    Content,
}

impl<'de> Deserialize<'de> for TagOrContent {
    fn deserialize<D: Deserializer<'de>>(d: D) -> Result<Self, D::Error> {
        struct Visitor;
        impl<'de> serde::de::Visitor<'de> for Visitor {
            fn visit_str<E>(self, v: &str) -> Result<TagOrContent, E> {
                match v {
                    "t" => Ok(TagOrContent::Tag),
                    "c" => Ok(TagOrContent::Content),
                    _ => Err(de::Error::unknown_field(v, &["t", "c"])),
                }
            }
        }
        d.deserialize_identifier(Visitor)
    }
}
```

## 4. Untagged —— `serde_derive/src/de/enum_untagged.rs`

```rust
// 源码: serde_derive/src/de/enum_untagged.rs (135 行)
// 核心思想: 缓冲输入,依次尝试每个 variant

fn deserialize<D>(d: D) -> Result<Self, D::Error> {
    // 1. 缓冲整个输入为 Content
    let content: _serde::__private::Content = Deserialize::deserialize(d)?;

    // 2. 依次尝试每个 variant
    // 第一次失败继续,最后一次失败则报错
    let deserializer = _serde::__private::de::ContentRefDeserializer::new(&content);

    // 尝试 variant 1
    if let Ok(v) = Variant1Deserializer::deserialize_with_content(deserializer) {
        return Ok(Event::Variant1(v));
    }

    // 尝试 variant 2
    if let Ok(v) = Variant2Deserializer::deserialize_with_content(deserializer) {
        return Ok(Event::Variant2(v));
    }

    // ...
    Err(de::Error::custom("data did not match any variant"))
}
```

### untagged 约束

```rust
// 1. untagged variant 必须在最后(否则前面的 variant 可能"吞噬" 后面的数据)
// 2. 只能有一个 untagged variant(因为 untagged 会 match 任何数据)
// 3. unit variant 会匹配 null,需要小心顺序

// 检查规则(源码: serde_derive_internals/src/check.rs):
fn check_variant_untagged(cx: &Ctxt, cont: &Container) {
    let mut allow_untagged = true;
    for variant in variants {
        if variant.attrs.untagged() {
            if !allow_untagged {
                cx.error("untagged variant must be after all others");
            }
        } else {
            allow_untagged = false;
        }
    }
}
```

## 5. 分支失败会回退吗? —— 匹配即提交

**tagged 系列 (external / internal / adjacent) 都不回退, 单遍完成**:

- 变体名 token 在 `EnumAccess::variant()` 时被**消费一次**, 格式的 token 流不可倒带
- `match` 命中分支后即"提交": 载荷反序列化失败 (如 `{"Move": {"x": "abc"}}`)
  直接向上传播, **不会回头尝试其他变体**
- 未知变体名直接 `Error::unknown_variant`, 不存在试探

```rust
// external 的生成代码 (概念):
fn visit_enum<A: EnumAccess<'de>>(self, data: A) -> Result<Event, A::Error> {
    let (field, variant) = data.variant::<__Field>()?;   // ← 变体名在这里被消费, 之后无法回头
    match field {
        __Field::Click => {
            // 这里的 ? 一旦失败, 整个 deserialize 就结束了, 不会去试 KeyPress
            let (x, y) = variant.struct_variant(&["x", "y"], ClickVisitor)?;
            Ok(Event::Click { x, y })
        }
        ...
    }
}
```

唯一的兜底手段:
- internal tagged 的 `#[serde(other)]` 变体: 只接住"未知 tag 值", **不重试载荷**
- `#[serde(untagged)]`: 唯一的"真回退", 但机制完全不同 —— 先缓冲、再逐个尝试:

```rust
// untagged (源码: serde_derive/src/de/enum_untagged.rs)
// 1. 整个输入先缓冲进 Content (serde 私有中间表示, 相当于 AST)
let content = Deserialize::deserialize(d)?;
// 2. 按声明顺序逐个尝试, 每个变体做一次完整 Deserialize,
//    失败就丢弃错误试下一个; 全失败返回最后一次尝试的错误
if let Ok(v) = T1::deserialize(ContentRefDeserializer::new(&content)) {
    return Ok(Event::V1(v));
}
if let Ok(v) = T2::deserialize(ContentRefDeserializer::new(&content)) {
    return Ok(Event::V2(v));
}
Err(de::Error::custom("data did not match any variant"))
```

untagged 的代价 (为什么会慢):
- 必须先把整个值读完, 无法流式解析
- Content 是持有的, `&'de str` 之类的借用会退化
- 顺序敏感: 第一个成功变体胜出, 要求各变体在数据形状上互斥

**结论**: 手写 Deserialize 时记住 —— **载荷失败不重试**。想支持"多形状"只有两条路:
untagged 交给 serde 缓冲重试, 或自己在 `deserialize_any` 里手工分派。

> 可运行演示: `demos/examples/08_why_visitor.rs` 第 4-5 节
> (手写 EnumAccess/VariantAccess 调用链 + untagged 式逐个尝试对比)

## identifier.rs —— 标识符枚举

```rust
// 源码: serde_derive/src/de/identifier.rs (477 行)
// 为 struct 字段和 enum 变体生成标识符枚举

// 对于 struct S { foo: i32, bar: String }
// 生成:
enum __Field {
    foo,
    bar,
}

// __Field 实现了 Deserialize:
impl<'de> Deserialize<'de> for __Field {
    fn deserialize<D: Deserializer<'de>>(d: D) -> Result<Self, D::Error> {
        struct __FieldVisitor;

        impl<'de> Visitor<'de> for __FieldVisitor {
            type Value = __Field;

            fn visit_str<E: de::Error>(self, v: &str) -> Result<__Field, E> {
                match v {
                    "foo" => Ok(__Field::foo),
                    "bar" => Ok(__Field::bar),
                    _ => Err(de::Error::unknown_field(v, FIELDS)),
                }
            }

            fn visit_bytes<E: de::Error>(self, v: &[u8]) -> Result<__Field, E> {
                match v {
                    b"foo" => Ok(__Field::foo),
                    b"bar" => Ok(__Field::bar),
                    _ => /* unknown_field error */,
                }
            }

            // 有些格式用数字索引代替字段名
            fn visit_u64<E: de::Error>(self, v: u64) -> Result<__Field, E> {
                match v {
                    0 => Ok(__Field::foo),
                    1 => Ok(__Field::bar),
                    _ => Err(de::Error::invalid_value(...)),
                }
            }
        }

        d.deserialize_identifier(__FieldVisitor)
    }
}
```
