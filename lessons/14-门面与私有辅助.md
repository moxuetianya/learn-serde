# 第十四章: serde 门面 crate 与私有辅助模块

**源码参考**: `serde/src/lib.rs`, `serde/src/private/{mod,de,ser}.rs`, `serde_core/src/lib.rs`

## serde crate —— 门面设计

`serde` crate 是一个**门面 (Facade)**,本身几乎不包含实现,而是重导出 `serde_core` 和 `serde_derive`:

```
用户代码
  │
  ▼
serde (门面)
  ├── serde_core  ── 核心 trait 定义
  ├── serde_derive ── proc-macro(可选, `derive` feature)
  └── src/private/  ── derive 生成代码所需的私有辅助
```

### 为什么需要门面?

1. **统一入口**: 用户只需要 `use serde::{Serialize, Deserialize}` 就能同时获得 trait 和 derive 宏
2. **私有辅助**: derive 宏生成的代码需要访问内部实现(Content、FlatMapSerializer 等),但不能暴露在公共 API 中
3. **版本同步**: 确保 serde_core + serde_derive 版本一致

### 门面实现

```rust
// 源码: serde/src/lib.rs
// crate_root! 宏展开后相当于:

// 1. 定义 lib 模块(std/core/alloc 的抽象层)
mod lib {
    pub use core::*;  // 或 std::*, 取决于 feature
}

// 2. 定义 tri! 宏
macro_rules! tri {
    ($e:expr) => {
        match $e {
            Ok(val) => val,
            Err(err) => return Err(err),
        }
    };
}

// 3. 重导出 serde_core
pub use serde_core::{
    de, ser,
    forward_to_deserialize_any,
    Deserialize, Deserializer,
    Serialize, Serializer,
};

// 4. 可选重导出 serde_derive
#[cfg(feature = "derive")]
pub use serde_derive::{Deserialize, Serialize};

// 5. 私有辅助模块
pub mod __private {
    pub use crate::private::{de, ser};
}
```

### Content —— 核心缓冲机制

```rust
// 源码: serde/src/private/de.rs (content 子模块)
// Content 是 serde 数据模型的内存表示,用于 untagged enum 等场景

pub enum Content<'de> {
    Bool(bool),
    U8(u8), U16(u16), U32(u32), U64(u64),
    I8(i8), I16(i16), I32(i32), I64(i64),
    F32(f32), F64(f64),
    Char(char),
    String(String),
    Str(&'de str),
    ByteBuf(Vec<u8>),
    Bytes(&'de [u8]),
    None,
    Some(Box<Content<'de>>),
    Unit,
    Newtype(Box<Content<'de>>),
    NewtypeVariant {
        name: String,
        variant: String,
        value: Box<Content<'de>>,
    },
    Seq(Vec<Content<'de>>),
    Map(Vec<(Content<'de>, Content<'de>)>),
    // ...
}

// Content 实现了 Deserialize,可以从任意数据构建
impl<'de> Deserialize<'de> for Content<'de> {
    fn deserialize<D: Deserializer<'de>>(deserializer: D) -> Result<Self, D::Error> {
        deserializer.deserialize_any(ContentVisitor)
    }
}

// ContentVisitor 将任何输入转为 Content
impl<'de> Visitor<'de> for ContentVisitor<'de> {
    type Value = Content<'de>;

    fn visit_bool(self, v: bool) -> Result<Content<'de>, E> {
        Ok(Content::Bool(v))
    }
    fn visit_str(self, v: &str) -> Result<Content<'de>, E> {
        Ok(Content::String(v.to_owned()))
    }
    // `de lifetime: 支持借用
    fn visit_borrowed_str(self, v: &'de str) -> Result<Content<'de>, E> {
        Ok(Content::Str(v))  // 零拷贝!
    }
    fn visit_seq<A>(self, mut seq: A) -> Result<Content<'de>, A::Error> {
        let mut v = Vec::new();
        while let Some(e) = seq.next_element()? {
            v.push(e);
        }
        Ok(Content::Seq(v))
    }
    // ...
}
```

### TaggedContentVisitor —— 内部标签枚举

```rust
// 用于 #[serde(tag = "type")] 枚举的反序列化
pub struct TaggedContentVisitor<T> {
    tag_name: &'static str,
    expecting: &'static str,
    value: PhantomData<T>,
}

impl<'de, T> Visitor<'de> for TaggedContentVisitor<T> {
    type Value = (T, Content<'de>);  // 返回 (variant, content)

    fn visit_map<A>(self, mut map: A) -> Result<(T, Content<'de>), A::Error> {
        let mut tag = None;
        let mut content = Vec::new();  // 收集非 tag 的键值对

        while let Some(key) = map.next_key::<TagOrContent>()? {
            match key {
                TagOrContent::Tag => {
                    tag = Some(map.next_value()?);
                }
                TagOrContent::Content => {
                    let k: Content = map.next_value()?;
                    let v: Content = map.next_value()?;
                    content.push((k, v));
                }
            }
        }

        let tag = tag.ok_or_else(|| de::Error::missing_field("tag"))?;
        Ok((tag, Content::Map(content)))
    }
}
```

### FlatMapSerializer —— flatten 序列化

```rust
// 源码: serde/src/private/ser.rs
// 展开 flatten 字段的序列化结果,合并到父级 serializer

pub struct FlatMapSerializer<'a, M: 'a> {
    map: &'a mut M,
}

// serialize_field 实际上调用 serialize_entry,
// 将 flatten 结构的字段展开到父级 map 中
impl<'a, M: SerializeMap> SerializeStruct for FlatMapSerializer<'a, M> {
    fn serialize_field<T: Serialize + ?Sized>(
        &mut self, key: &str, value: &T
    ) -> Result<(), M::Error> {
        self.map.serialize_entry(key, value)
    }
}
```

## 为什么 tri! 代替 ? 操作符?

```rust
// 源码: serde/src/lib.rs (通过 crate_root! 生成)
macro_rules! tri {
    ($e:expr) => {
        match $e {
            core::result::Result::Ok(val) => val,
            core::result::Result::Err(err) => {
                return core::result::Result::Err(core::convert::From::from(err));
            }
        }
    };
}
```

serde 源码自身使用 `tri!` 代替 `?`,因为 `?` 会导致编译器为每个使用点生成大量 LLVM IR,而 `match` 版本在编译时效率更高(据 serde 团队测量,快了 5.5-9%)。

// 源码: serde_core/src/lib.rs
